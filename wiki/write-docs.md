### 2. Previewing the markdown

To preview the markdown file you are currently writing -

- Just press `cmd shift v`

A new preview tab should pop-up and you should be able to see the preview. The Markdown styling should look similar to the Github's, thanks to the [Markdown Preview Github Styling](https://marketplace.visualstudio.com/items?itemName=bierner.markdown-preview-github-styles) extension we installed earlier.

### 3. Best Practices

When writing docs, some common practices are being followed in all the docs. To keep things consistent, it's recommended to follow the same formattings in the new doc you are about to write. Here are some of the key pointers you should be looking at make things efficient and work best for you.

#### 3.1. Format on Save

Make sure you have turned on VS Code's `Format on Save` option so that the spacings, lists etc. in your document are always formatted. To turn on the `Format on Save` option -

- Press `cmd ,`
- Type in `Format on save` in the search box
- Check it if it's not enabled

#### 3.2. Title

- Document's title should be centered. You can use the below snippet for adding the title to your document -

  ```html
  <header>
    <h1 align="center">Writing Documentations</h1>
  </header>
  ```

- Make sure to have a short, clear and crisp title that best represents the purpose of the doc. Avoid writing long statements in the title like this bad boy here -

  <header>
    <h1 align="center">The first time I broke prod and cried the whole night</h1>
  </header>

#### 3.3. Changelogs

If you are writing a new dcoument or changing an existing one, always make sure to add a changelog, so that people know your contributions towards a better society 🥹

- Changelogs are added in the `<summary> </summary>` tag along with the title of the doc. Here's one snippet for your reference -

  ```html
  <header>
    <h1 align="center">Writing Documentations</h1>
    <details>
      <summary align="center"><b>Changelog</b></summary>

      | Version | Date | Creators | Reviewers | Remarks | | ------- | ------------ |
      ------------------ | --------- | ------------- | | 1.0 | Feb 01, 2023 | `Ritesh Ganjewala` |
      Initial Draft |
    </details>
  </header>
  ```

#### 3.4. Outline/Table of Contents

Make sure to add a table of contents for your document below the title and the changelogs. Wait!!! Don't do it manually.

To add a table of contents, just do the following -

- Press `cmd shift p`
- Type `Markdown All in One: Create Table of Contents` and click on the relevant option

It'll generate a table of contents wherever your cursor is. Also, whenever you change an heading or sub-heading it updates automatically on save.

#### 3.5. Heading

All the first-level Headings in your doc must be a `###` (h3) heading in markdown, like this -

```
### Make a cheese-burst Pizza
```

#### 3.6. Subheading

All the second-level Headings or you may say Subheadings must be `####` (h4) heading in markdown, like this -

```
#### Take lots of cheese and some dough
```

#### 3.8. Section Numbers

Yep, no manual efforts again please. Make sure to add section numbers to your headings/sub-headings in your doc. To add section numbers -

- Press `cmd shift p`
- Type `Markdown All in One: Add/Update section numbers` and click the relevant option

_It's pretty nifty, right? [Markdown All in One](https://marketplace.visualstudio.com/items?itemName=yzhang.markdown-all-in-one) extension is fun_

#### 3.9. Notes

To add a note in your document -

- Use this format in markdown

  ```
  > **Note -** some serous note here
  ```

It should look something like this

> **Note -** May I have your attention please? Train num...

#### 3.10. Codeblocks

- Avoid pasting screenshots of your code, use codeblocks in your markdown instead.

- Always add language highlighting for your codeblock if available. Similar to this js snippet -

  ```js
  const pi = 3.14159265; // or just consider it to be 3 🗿
  ```

- If you are adding a codeblock under a ordered/unordered list item, make sure it's properly indented like the one above, not the one below

```
This shouldn't be left indented if it is related to the list item
```
